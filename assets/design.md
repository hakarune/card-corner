# Card Corner — art asset guide

This is the reference for making real art for the game: exact sizes,
file naming, SVG vs. PNG, and how a new file actually gets into the game.
It's written so **anyone** — you on desktop, you on your phone, or someone
else entirely — can drop in a correctly-named file and have it show up,
with no code changes needed for anything already listed below.

## The short version

1. Make your art (SVG or PNG, your choice per asset — see "SVG or PNG?"
   below) at the size given in the tables further down.
2. Save it under `assets/source/<category>/<key>.svg` (or `.png`), using
   the exact `key` from the tables — lowercase, underscores, no spaces.
3. Run `python tools/build_assets.py` once. It converts/resizes
   everything in `assets/source/` into finished PNGs under `ui/assets/`,
   which is what the game actually loads.
4. Launch the game and look. If something's missing, corrupted, or you
   just haven't made it yet, **the game silently falls back to the
   built-in procedural drawing** for that one piece — nothing crashes,
   nothing looks broken, it just uses the placeholder art until you
   replace it. That's true today for every category on this list, since
   only the 3 card backs exist as real art so far.

## SVG or PNG?

Either works — the game only ever loads a PNG at the end (`tools/build_assets.py`
handles the conversion), so this is purely about what's easiest for you to make
and edit:

- **SVG** is the better choice for anything you might want to *resize or
  re-theme later without redrawing it* — flat-color patterns, icon-style
  line art, anything vector-friendly. It also means the PNG can be
  regenerated at a different resolution later without you touching the art
  again.
- **PNG** is fine — genuinely, not a fallback-quality option — for
  anything painterly, textured, or easier to just draw/paint directly
  (a scanned drawing, a photo-textured background, anything from a raster
  tool). Just export it at (or above) the size listed for that asset, with
  a transparent background where noted.
- If both an `.svg` and `.png` exist for the same key, the SVG wins (it's
  treated as the source of truth; the PNG next to it is likely just an
  export preview from your design tool and gets ignored by the build
  step).

## Folder structure

```
assets/
  design.md          <- this file
  image-list.md       <- your running wishlist of future icons (not all wired into code yet -- see note below)
  source/             <- YOU edit this. SVG or PNG, by category/key.
    cards/backs/
    icons/items/
    icons/animals/
    icons/launcher/
    icons/special/
ui/assets/            <- GENERATED by tools/build_assets.py. The game loads from here. Don't hand-edit.
tools/build_assets.py <- the conversion script (run this after editing assets/source/)
```

## Card backs

The three finished patterns are exactly this category. Each is the
**whole card back**, edge-to-edge — the game draws a thin border on top
of it, but the pattern itself should fill the entire canvas with no
padding.

| Key | Used by | Real on-screen size (logical px) | Make it at (4x headroom for large/4K screens) | Source file |
|---|---|---|---|---|
| `go_fish` | Go Fish card backs | 70 × 100 | **280 × 400** | `assets/source/cards/backs/go_fish.svg` |
| `old_maid` | Old Maid card backs | 70 × 100 | **280 × 400** | `assets/source/cards/backs/old_maid.svg` |
| `memory` | Memory face-down tiles | 125 × 125 (square) | **500 × 500** | `assets/source/cards/backs/memory.svg` |

Why 4x: the game renders everything to a fixed 1024×720 canvas and then
scales that whole canvas up to fill the real window — on a large or 4K
monitor that can be a 3-4x upscale, so a card back made at exactly
70×100 would look soft/blurry once stretched. Made at 4x, it stays crisp
on a big screen and still shrinks down fine on a small one.

**The game's name is *not* part of the art.** The "GO FISH!" / "OLD MAID"
/ "MEMORY" lettering is drawn by the code on top of your pattern (so it
stays sharp at any size and doesn't need to be redrawn if wording ever
changes) — you don't need to letter it into the artwork yourself.

**Non-uniform sizes across the three are completely fine.** Each one is
loaded and scaled independently against its own game's card size — they
never need to match each other's dimensions or aspect ratio.

**How each one gets treated at build time** (this is handled by
`tools/build_assets.py`, not something you need to do by hand — noted
here so you know what to expect if you look at the generated output):

- `go_fish`, `memory`: used **as one whole image**, scaled to fit the
  card/tile directly. Comparison renders at true in-game size showed
  these already read clearly at that size — cropping and repeating them
  smaller actually lost detail (especially the circuit-board look, which
  got chunky/blocky when shrunk-and-tiled).
- `old_maid`: cropped to the center **half** of the source and **tiled
  2×2** to fill the card. At true card size, using the whole image
  directly packed the faces in so small they stopped reading as faces;
  tiling a bigger crop keeps them recognizable.

If you redesign one of these patterns, it's worth re-running the
comparison check (ask for a fresh mockup) rather than assuming the same
treatment is still right — it's genuinely pattern-specific, not a fixed
rule.

## Icons (items, animals, launcher tiles, the Old Maid card)

Everything in this section shares **one size and shape rule**, which
keeps this simple: make a **square canvas, 512 × 512px, transparent
background**, with the subject centered and not touching the edges. The
game fits it into whatever space it needs (never stretching it — it's
always scaled down proportionally and centered), so one square icon works
correctly whether it ends up on a portrait Go Fish card or a square
Memory tile.

### Item icons (Go Fish's card faces / Memory's tile faces)

These are the everyday-object icons (currently procedurally drawn) that
appear on Go Fish's hand cards and Memory's face-up tiles — both games
share the same 13-item set.

| Key | Currently used for |
|---|---|
| `sun`, `moon`, `star`, `heart`, `flower`, `fish`, `bird`, `tree`, `house`, `umbrella`, `apple`, `ball`, `boat` | Go Fish + Memory item deck (13 ranks) |

Path: `assets/source/icons/items/<key>.svg`

### Animal icons (Letter Match's "Animals" mode)

| Key | Currently used for |
|---|---|
| `bird`, `cat`, `dog`, `fish`, `lion`, `owl`, `pig` | Letter Match's Animal↔Letter mode (7 letters) |

Path: `assets/source/icons/animals/<key>.svg`

`bird` and `fish` exist in both the items and animals sets above — those
can genuinely be the same artwork in both folders if you want, since it's
the same subject in both places; nothing requires them to differ.

### Launcher tile icons

The icon inside each of the four big buttons on the main menu (not the
whole button — the colored tile background and the label text underneath
stay code-drawn either way, so this is just the picture in the middle).

| Key | Tile |
|---|---|
| `go_fish` | Go Fish |
| `old_maid` | Old Maid |
| `memory` | Memory |
| `letter_match` | Letter Match |

Path: `assets/source/icons/launcher/<key>.svg`

### The Old Maid card's own illustration

The one card the whole game revolves around gets its own distinct face
(not a reused item icon, not the card back) — currently a procedurally
drawn granny face with glasses.

| Key | Used for |
|---|---|
| `old_maid_card` | The face shown on the actual Old Maid card in every player's hand |

Path: `assets/source/icons/special/old_maid_card.svg`

### About `image-list.md`

That file is your running wishlist and isn't limited to the 13+7 icons
above — it's fine to keep adding to it. Just know that dropping a new PNG
named e.g. `elephant.png` into `icons/animals/` won't do anything by
itself yet, because the game only draws icons for keys it knows about
(the 13 item ranks and 7 animal letters listed above). Adding a genuinely
new one also needs a small code change to register it — ask and it's a
quick addition, not a redesign.

## Launcher tile — full custom art (optional, later)

If you ever want to redo a whole main-menu tile as one piece of art
(background + icon together, not just the icon), rather than keeping the
solid-color background: real tile size is 420 × 220px; make it at
**1260 × 660** (3x). This isn't wired up yet and isn't needed to use any
of the icon-based options above — noted here so the number exists if you
want it.

## The fallback safety net

Every category above already has a working built-in fallback (the
current procedurally-drawn version) — this isn't something to build
later, it already works this way for every piece of art that doesn't
exist yet. If a file is missing, fails to load, or gets corrupted, the
game just draws the built-in version for that one asset and carries on
normally. This means:

- You can replace assets one at a time, in any order, and the game stays
  fully playable throughout.
- A bad export, an accidental deletion, or a half-finished `.svg` never
  breaks the game — worst case, that one card/icon looks like the
  original placeholder art until it's fixed.
- There's nothing to "turn on" — real art and placeholder art are drawn
  through the exact same code path, just with a different source.
